# Source code and experiments

Complete source for the ESP32 smart home surveillance study: firmware, formal specifications,
experiment harnesses, analysis scripts, figure generators, test suites and both documents.

Archive: `COMPLETE_SOURCE_CODE_AND_EXPERIMENTS.zip`
Built by: `tools/build_source_archive.py`
Contents: 209 files, 7.5 MB
Repository commit: see `report/generated/meta.tex`

`MANIFEST.txt` inside the archive lists the SHA-256 of every included file, and every excluded
path with the reason it was excluded.

## What is not in the archive

| Excluded | Reason |
|---|---|
| `secrets.h` | may contain real credentials. `secrets.example.h` **is** included — its demonstration key is published on purpose, and the build refuses to accept it as a real key |
| `*.key`, `*.pem`, `*.crt`, `passwd*` | certificate and password material generated by the broker testbed. Regenerate with `experiments/broker/setup.sh` |
| `tla2tools.jar` | 4.5 MB binary; `formal/run_tlc.sh` downloads it |
| `corpus_repos/` | third-party source fetched for the corpus study. The fetched metadata and rejection counts are included in `corpus.json` |
| `docs/media/` | demonstration video and GIF, 11 MB, not source |
| `FINAL_SUBMISSION_PACKAGE/` | copies of files already present at their own paths |
| build output, LaTeX intermediates, caches, model-checker traces | regenerate from source |

The archive builder refuses to produce an archive at all if it finds anything resembling a
private key or certificate body in an included file. That check is verified by a positive
control: planting a file containing a key block makes the build fail.

## Prerequisites

- `arduino-cli` with the `esp32:esp32` core, plus the `Adafruit SSD1306`, `Adafruit GFX` and
  `PubSubClient` libraries — firmware only
- GCC 13 or later, for the host tests and experiment harnesses
- Python 3.11 or later; `pip install -r requirements.txt`
- Java, for `tla2tools.jar`
- Mosquitto 2.0.x and OpenSSL, for the live-broker experiment
- TeX Live, for the manuscript and the report

## Unpack and run

```bash
unzip COMPLETE_SOURCE_CODE_AND_EXPERIMENTS.zip -d smart-home-automation
cd smart-home-automation
```

Paths inside the archive match their paths in the repository, so every command below runs
unchanged after unpacking.

### Verification

```bash
bash tests/host/run_tests.sh      # 129 assertions, incl. 3 negative build tests
bash formal/run_tlc.sh            # 3 configurations; the third MUST report a violation
python3 experiments/test_conformance.py
python3 experiments/test_harness.py
python3 experiments/corpus/test_rule.py
```

A negative build test passes when the compiler **refuses** the defective configuration. A build
that succeeds there is a test failure. Likewise `formal/run_tlc.sh` treats a passing third
configuration as a build failure: that configuration exists to prove the invariant is
falsifiable.

### Experiments

```bash
bash experiments/run.sh            # E1, E2: 6,000 adversarial trials
bash experiments/run_ablation.sh   # E3: 12 configurations, 3,600 trials
bash experiments/broker/setup.sh   # E6: generates the CA, certificates, passwords, ACL
bash experiments/broker/run.sh     # E6: 8 scenarios against Mosquitto 2.0.18
```

E4 (3,000,000 fuzz iterations) and E5 (180 sensitivity cells) are built and run by
`experiments/run.sh`. E7 requires a GitHub token and re-fetches third-party repositories, so it
will not return the same 135 projects; the fetched corpus is included so the analysis is
reproducible without re-fetching.

### Figures and documents

```bash
python3 docs/figures/make_diagrams.py
python3 experiments/make_ablation_figures.py
python3 experiments/validate_figures.py        # recomputes every plotted value from raw records
python3 experiments/check_figure_type.py       # fails if any label prints below 6 pt
python3 experiments/check_figure_fit.py        # measures every label in the real font

cd paper  && pdflatex manuscript.tex   # three passes
cd report && pdflatex report.tex       # three passes, for the ToC, LoF and LoT
```

### Firmware

```bash
cp firmware/smart_home/secrets.example.h firmware/smart_home/secrets.h
# Edit secrets.h: set Wi-Fi credentials and REPLACE the demonstration keys.
arduino-cli compile --fqbn esp32:esp32:esp32 firmware/smart_home \
  --build-property "compiler.cpp.extra_flags=-DAUTH_COMMANDS=1"
arduino-cli upload --fqbn esp32:esp32:esp32 -p /dev/ttyUSB0 firmware/smart_home
```

## Hardware experiments

`experiments/hardware/` contains the probe firmware, the serial collection script and the
analysis script with its pre-registered Mann–Whitney U test.

**No hardware data exists.** Conditions A–D were not executed; no physical ESP32 was available.
`results_hw_TEMPLATE.csv` carries the schema (`condition,index,latency_us`) and no rows. The
analysis script was verified end to end on explicitly synthetic input as a script self-test, and
that synthetic file was deliberately not committed so it cannot be mistaken for data.

The procedure is in `docs/HARDWARE_A_TO_C_RUNBOOK.md` and the protocol, with the pre-registered
test and sample sizes, in `docs/HARDWARE_VALIDATION_PLAN.md`. The test was fixed before any data
existed and must not be substituted after seeing measurements.

## Reproducibility

Seeds are fixed at 1000, 2000 and 7. The ablation harness forks per trial, so no trial can
influence the next through accumulated state. All statistics use the Python standard library
only, so no external package version can change a reported value. Every figure SVG regenerates
byte-identically; the PDFs differ only in embedded creation timestamps.

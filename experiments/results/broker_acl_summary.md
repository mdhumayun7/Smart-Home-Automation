# Access-control validation against a real Mosquitto broker

Generated by `experiments/broker/validate_acl.py`. **Evidence category: testbed measurement.** Unlike the arms in `ablation_summary.md`, these are observations of a real broker: Mosquitto 2.0.18 over TLS 1.2 with a private CA, password authentication, and per-client ACLs.

A note on method. MQTT 3.1.1 has no return code meaning "refused by policy": the broker acknowledges a QoS 1 publish and then silently discards it. A PUBACK is therefore not evidence of delivery, and the `puback` column below shows that directly. Every scenario is decided by whether a subscriber holding the device's identity actually received the message.

Reproducibility differs from the simulations in this repository. Those regenerate byte-identically from fixed seeds. This one talks to a live broker, so the log timestamps and the randomly generated client identifiers differ on every run; the scenario outcomes, the topics and the message sizes do not. Re-running should reproduce every verdict in the table below and both denial lines, not the exact bytes of this file.
